# Аудит звука двигателя

Цель — независимо проверить исходный генератор для браузерного стенда звука двигателя и подготовить критерии приёмки для исполнителя. Код игры обследован на `c9faa71a16fde48c2beb0db362189b82bb958149`. Игровой код, физика и сцены в этой ветке не менялись.

## Что сделано

- Проверен [генератор Antonio-R1 на `c76c5ad`](https://github.com/Antonio-R1/engine-sound-generator/tree/c76c5adb9e63f5a54fb0def3b97e8e0ac1a7dea1). При 3000 об/мин переключение параметра газа с 0 на 1 оставило все три канала идентичными в детерминированном прогоне на 44,1 и 48 кГц.
- В Chromium 156 через `OfflineAudioContext` подтверждён остаточный сигнал при 0 об/мин и после остановки с 3000 об/мин. Измерение выполнено с 1-й по 3-ю секунду. Значения в JSON относятся к сырым выходам генератора до микширования.
- Из чтения кода: случайная поправка нарушает равномерный ритм вспышек четырёх цилиндров. При установившемся среднем поправки интервалы составляют 180°, 270°, 180° и 90° угла коленвала. Обработчик порта пересоздаёт профиль и очищает задержки. Отправка в исходный обработчик неполного сообщения с RPM приводит к ошибке. Длины задержек в отсчётах и часть коэффициентов фильтров требуют адаптации к частоте дискретизации.
- Проверена будущая интеграция с Three.js. При выходе из машины физические RPM перестают обновляться. Нужен явный переход состояния источника. Аудиовремя и время симуляции расходятся при длинных кадрах. При маршрутизации трёх выходов Worklet требуется выбирать индекс каждого выхода отдельно. [Записки по интеграции](tools/engine-audio-audit/integration/findings.txt).

## Файлы и воспроизведение

[Материалы аудита](tools/engine-audio-audit/) содержат скрипты Node и Chromium и четыре исходных отчёта JSON. Две копии Worklet нужны существующим скриптам. Они отличаются одним завершающим переводом строки. Точная копия соответствует Git blob `c2841d6f0dfd13e4d78853bbb2bd9c8d9451426e`. Рядом сохранена лицензия MIT. Неизменённые справочные копии файлов игры и Three.js доступны по ссылкам из записок.

Запускать в копии папки аудита, поскольку скрипты перезаписывают файлы результатов. Требуется Node.js. Для браузерных прогонов также нужны доступный Node модуль `playwright` и Chromium по пути `/usr/bin/chromium`.

```sh
node audit.cjs
node browser-audit.cjs
node browser-stop-audit.cjs
```

Браузерные прогоны читают `results.json` с параметрами до запуска. Случайный шум в Chromium даёт небольшие отличия амплитуд между запусками. Отдельные `audit-legacy-parameters.cjs` и `results-legacy-parameters.json` сохраняют ранний прогон на параметрах другого примера. Большие амплитуды того прогона относятся к этим параметрам. При его повторе скрипт запишет `results.json`, поэтому его следует запускать в отдельной копии папки.

## Что осталось

Следующий результат зависит от исполнителя звука: коммит или патч стенда, запись двух нагрузок на одинаковых оборотах и лог переходов. Критерии для первой проверки: выход затихает после остановки, при 3000 об/мин без случайной поправки вспышки идут каждые 10 мс, обновление телеметрии сохраняет фазу и состояние задержек. Слуховая оценка, нагрузка на аудиопоток в реальном времени и запуск стенда в игре ещё не выполнялись. Для интеграции достоверную нагрузку должен предоставить модуль физики. На изолированном стенде её задаёт тест.
