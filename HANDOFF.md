# Городская жизнь и трафик

Снимок работы из Codex Cloud. Ветка `codex/city-lifecycle-01` начата от `c9faa71a16fde48c2beb0db362189b82bb958149`. Проверенный кандидат и исходный отчёт сохранены в коммите `cfa9d55`. [Черновой PR #3](https://github.com/depthd/newlifeboon/pull/3)

## Цель и результат

Ближайшая цель приёмки — пройти цепочку «дом → магазин → дом» пешком и на машине, сохраняя идентичность жителя, машину и место парковки. При искусственной задержке старый код создавал второго пешехода с тем же номером или менял маршрут ещё не прибывшей машины.

Кандидат ждёт завершения активной поездки перед следующим выходом. Очередь хранит исходные сутки, а проверка занятости учитывает водителя, пассажиров и сопровождаемых детей. В испытаниях сценарий продолжался после снятия блокировки, в том числе после полуночи.

## Статус и известные проблемы

- Штатный `npm run life` на исходном коммите проходил 41 из 41 проверок. На кандидате проходят **40 из 41**. Сбой связан с вечерней парковкой.
- У семи из восьми спорных машин собственное место было занято при выборе и освободилось к концу проверки. Тест использует занятость в конце часа. У машины `682` место было свободно, но на расстоянии около 5,4 м, тогда как код выбора требует более 8 м.
- При постоянной блокировке очередь растёт. Состояние жителя внутри здания по-прежнему берётся из расписания. Полная цепочка до возвращения домой, наблюдение движения в браузере и стоимость расчёта остаются открытыми для приёмки.
- При продолжении сначала проверить парковочную метрику по моменту выбора, отдельно разобрать случай `682` и повторить `life` вместе с проверками задержек. Подробности и исходные логи сохранены в [журнале приёмки](docs/technical-review.md) и [каталоге диагностики](docs/review-evidence/city-lifecycle/).

## Файлы и зависимости

- `src/city/жизнь.ts` — очередь следующих выходов, завершение текущего движения и учёт пассажиров.
- `tools/review-blocked.ts`, `tools/review-lifecycle.ts`, `tools/review-release.ts`, `tools/review-car-release.ts` — воспроизведение дублей, удержание движения и возобновление поездок.
- `tools/review-parking.ts`, `tools/review-parking-transitions.ts` — вечерняя парковка, итоговый снимок и занятость кармана в момент выбора.
- `STATE.md`, `docs/technical-review.md`, `docs/city-lifecycle-candidate.patch`, `docs/review-evidence/city-lifecycle/` — состояние ветки, журнал, исходный патч и результаты. В `archive/` лежат оригиналы дополнительных диагностических скриптов и выводов из рабочей папки. Импорты в архивных скриптах отражают исходное расположение файлов.

Кандидат опирается на существующие `traffic.ts`, `walkers.ts` и расписания из `житель.ts`. Для проверки достаточно этой ветки и зависимостей из `package-lock.json`. Ветка автомобильной физики и работа по звуку для неё не требуются.

## Как проверить

```sh
npm ci
npm run build
npm run traffic -- город
node --experimental-strip-types tools/review-blocked.ts
node --experimental-strip-types tools/review-lifecycle.ts
node --experimental-strip-types tools/review-release.ts
node --experimental-strip-types tools/review-car-release.ts
npm run life
node --experimental-strip-types tools/review-parking-transitions.ts
```

Сборка, трафик и проверки задержек прошли в сохранённых запусках. Типизация и два сценария продолжения движения были повторно проверены при сохранении кандидата. `life` воспроизводит один провал, а парковочный скрипт печатает подробности выбора места и результат критерия. Прогон с удержанием на 25 игровых часов является искусственным испытанием.
