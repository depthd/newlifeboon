## Цель и выбранный подход

Исследовать убедительный звук двигателя для Three.js, затем по отдельному
разрешению подготовить изолированный моно-прототип на AudioWorklet. Область —
только звук двигателя. Физика, трафик, город и общие игровые интерфейсы не менялись.

Выбран процедурный кандидат: возбуждение цилиндров, впуск/выпуск и акустические
волноводы на основе Antonio-R1/engine-sound-generator, коммит
`c76c5adb9e63f5a54fb0def3b97e8e0ac1a7dea1`, MIT. Лицензия и исследованная версия
сохранены в `docs/audio-reference/`. Свои тестовые WAV генерируются этим кодом;
сторонние записи двигателя в поставку не включены. Профиль — условный рядный
четырёхцилиндровый четырёхтактный двигатель, не калиброванный Renault K7M.
Генерируемые лупы рассматривались как резерв по вычислительной стоимости, но не как
способ исправить неубедительный тембр. Их реализация отсутствует.

## Что сделано

- Отдельная страница `audio-lab.html`, собственная Vite-конфигурация и команды
  `audio:dev`, `audio:build`, `audio:check`.
- DSP с непрерывной фазой, задержками и фильтрами, рассчитанными для фактической
  частоты дискретизации; нагрузка влияет на возбуждение и смесь компонентов.
- Один живой AudioContext и AudioWorkletNode после пользовательского действия;
  громкость, mute, stop/re-enable, ручной режим, пауза и продолжение.
- Команды с аудиовременем и sequence, сглаживание параметров, отдельное
  планирование дискретных событий. В активном режиме после 250 мс без свежих
  данных выход затухает за 100 мс; ручной режим не имеет такого тайм-аута.
- Сценарии холостого хода, 750–5800 RPM, нагрузок на одинаковых RPM, отключения
  сгорания, переключений, ограничителя и ступенчатой реакции.
- Захват моно-WAV и синхронной телеметрии, браузерные проверки, внешний анализ
  PCM и 12 фрагментов нагрузок с выровненным RMS.
- Два дефекта, найденные независимым проверяющим, исправлены: отказ команды при
  переходе active → manual и потеря коротких событий ограничителя при 15 Гц.

## Как проверить

Для исходников нужны Node.js 22.12+ или 24, npm; для автоматизации — Chromium,
по умолчанию `/usr/bin/chromium` (можно задать `CHROMIUM_PATH`).

```sh
npm ci
npm run types
npm run audio:build
npm run audio:dev
```

Открыть `http://localhost:5200/audio-lab.html` и нажать «Включить звук».
Запрос частоты задаётся `?sr=44100` / `?sr=48000`; фактическую частоту смотреть
в интерфейсе и журналах. При работающем сервере, во втором терминале:

```sh
npm run audio:check -- /tmp/engine-audio-recheck
node docs/audio-reference/check-throttle.cjs
python3 tools/audio-analysis.py /tmp/engine-audio-recheck
```

Последняя команда требует NumPy и SciPy. В исходном анализе использованы версии
2.3.5 и 1.17.0 соответственно. Новый вывод направляется в отдельную папку, чтобы
не перезаписать сохранённые измерения. При недоступном домашнем npm-кеше можно
использовать `npm ci --cache /workspace/work/npm-cache --ignore-scripts`.

Для проверки архива и готовой поставки:

```sh
cd artifacts/engine-audio
sha256sum -c SHA256SUMS
python3 -m zipfile -t engine-audio-prototype.zip
python3 -m zipfile -e engine-audio-prototype.zip /tmp/engine-audio-snapshot
cd /tmp/engine-audio-snapshot/dist-audio
python3 -m http.server 5200 --bind 127.0.0.1
```

Стенд: `http://localhost:5200/audio-lab.html`. Для записей отдельно обслужить
`/tmp/engine-audio-snapshot/evidence` на порту 5201 и открыть `/index.html`.
Ссылка на ZIP в этой извлечённой галерее не содержит вложенную копию самого
архива; использовать исходный ZIP из ветки. Все WAV и журналы находятся рядом.

- Chromium 156.0.8078.79: 20 offline-рендеров, 8 живых записей и проверки
  жизненного цикла; фактические 44100/48000 Гц; обновления 15/30/60/120 Гц;

## Не доделано и известные ограничения

- Прослушивание НЕ выполнено. Убедительность тембра, отсутствие слышимых щелчков
  и сходство с реальным мотором не подтверждены графиками и формулами.
- Нет подходящего эталона K7M с известными RPM, нагрузкой и условиями записи.
- Не измерены изолированное время DSP на живой блок, аппаратный выход,
  драйверные пропуски и акустическая задержка. Время offline-рендера не является
  такой оценкой CPU.
- Фоновая вкладка, мобильные устройства и другие браузеры не приняты.
- Нет подключения к машине, пространственного звука, салона и звука трафика.
  Нет сравнения стоимости машины игрока и множества окружающих автомобилей.
- `load01` в стенде — тестовая интенсивность сгорания. Это не положение газа
  и не подтверждённая нагрузка автомобиля; переключения и отсечка также заданы
  сценарием, а не приходят из трансмиссии.

## Зависимости от других задач и следующий шаг

Стенд автономен. Для игровой интеграции нужны согласованные данные от физики:
RPM коленвала, нагрузка/момент со знаком и понятной нормировкой, газ отдельно,
передача, сцепление, состояние двигателя и разрешение сгорания, реальные события
переключения/ограничителя, время и последовательность сообщений. Какие именно
поля физика реально выдаёт, нужно проверить на её выбранной версии. Текущий
игровой RPM нельзя считать проверенной физической телеметрией только потому,
что стенд умеет его воспроизводить. Физику в этой задаче не исправлять.

Следующее решение — техническая проверка сохранённой версии и прослушивание
с реальным эталоном. Если синтез неубедителен, рассмотреть лицензированные записи
или гибрид; генерирование лупов само по себе тембр не улучшит. Реализация
интеграции требует отдельного задания. При последующем сборе веток вероятны
пересечения по `STATE.md` и `package.json`; выбирать изменения отдельно, а не
заменять эти файлы целиком. WIP и старую ветку не удалять и не переписывать.
